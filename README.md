# 微信本地工作台 · 搭建引导

一份写给 AI 的施工参考：在你的电脑上，把本机微信聊天记录变成一个自己定义的工作台。
它不提供成品软件，只提供判断、路径与经验。

本文件供人阅读。AI 执行时以 `SKILL.md` 为准。

---

## 这个 skill 是怎么回事

适用场景：你希望基于**自己电脑上**的微信聊天记录做一个只有自己用的工具——
翻查记录、管理客户、统计群里的事，都算。

它做三件事：

1. **问清需求**——把「我想做个微信工具」变成可以动手的需求；
2. **给路线**——哪些技术路径已经验证通过、关键步骤在哪、哪里会翻车；
3. **荐资源**——界面该用哪类视觉风格资源（数据获取层已内嵌，见下文）。

它不提供：

- 任何组件、可运行程序、开箱即用的成品；
- 任何数据、示例数据或真实账号信息；
- 代为执行批量读取或导出。

唯一接近代码的部分，是数据获取分册里的**最小验证片段**——只保留能自检方向对不对的核心几段，
不构成可直接运行的工具。

## 为什么刻意不提供工具

这是设计选择，出于对生存环境的判断。

围绕本机微信数据的工具，一旦被封装成「装好即用」的成品——一键解密、一键导出全部聊天记录——
会显著提高被平台方判定为违规工具的概率，skill 本身也就活不长久。

这个判断来自现实观察：同类工具已经死过很多批，原因往往不在于技术做不到，
而在于暴露面太大——功能越完备、越接近成品，越容易被识别、被处理、被警告下架。

因此本 skill 主动降低**功能层**的便捷性：不打包脚本、不给即用接口、不代跑批量任务。
把实现交回使用者的 AI，一步一步做出来。

代价是上手更慢，收益是能长期存在。

对应的补偿放在**引导层**：问题问得清、坑标得明、每步都有验证方法、答不上来有兜底。
功能上不开箱即用，体验上不卡壳——这两条同时成立，才是这个 skill 的立足点。

## 数据获取能力已内嵌（模块名沿用 wechat-wcdb-local-extract）

密钥提取、库解密、消息与媒体提取的方法、参数与坑，**已完整内嵌在本 skill 内**，
模块名沿用 `wechat-wcdb-local-extract`。**装本 skill 一个就够，不需要另装外部 skill。**

| 层 | 在哪 |
|---|---|
| 数据获取（密钥 / 解密 / 消息提取） | `references/02-data-layer.md` |
| 媒体解密（图片 / 表情 / 视频 / 文件 / 视频号） | `references/03-media-layer.md` |
| 需求引导、架构选型、界面资源推荐 | `SKILL.md` 与 `04`、`05` 分册 |

这样安排的原因：原来的独立 skill 虽然能用，但脚本里留了不少要现场调试的坑，
使用者往往卡在这一步。把**调好的结论**内嵌进来，省掉这段弯路；
内嵌的形态停在「方法 + 最小验证片段」，不升级成成品，以维持前面说的生存策略。

## 怎么用

1. 装好本 skill（数据获取能力已内嵌，无需另装）；
2. 对 AI 说清楚你想做什么（一句话就够，说不清也能走默认形态）；
3. AI 按 `SKILL.md` 的主流程问你七个问题，一次一个；
4. 答完（或答不上来走默认）后，AI 给出架构方案，你和它一起一步步搭。

七问分四组：可行性（环境、账号、目标）、范围（会话、时间）、界面与功能（风格、功能）。
图片、视频、文件、表情这些媒体**默认全部包含**，不单独问。
目标说不清时走**默认形态**：按选定的范围与布局，搭一个简要工作台，之后由你自行修改扩展。

## 边界与承诺

- 只处理**使用者本人设备上**的数据；
- **不对微信目录做任何修改**——不写入、不改动、不删除、不改微信设置、不注入微信进程，只读取副本；
- 不代跑批量导出，不上传，不外传；
- 不提供成品组件。

## 适用范围

- 适用：Windows 10 / 11 + 微信桌面版 4.x（该账号至少在本机登录过一次）；
- 不适用：手机微信、macOS、企业微信与公众号后台数据。

目标账号若从未在本机登录过，需要先在本机登录该账号，并从手机端同步聊天记录，
之后才能开始——这是硬性前置条件。
