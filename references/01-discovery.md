# 01 · 七问怎么问

> SKILL.md 第 2 节是速查表，本篇是**照着念的展开版**：每题给可直接说出口的话术、
> 为什么要问、不同答案会把架构带向哪里、答不上来时怎么给选项。

## 提问总则

1. **一次只问一个**。七个问题一次抛出，用户会随口答，后面全部返工。
2. **不许抛术语**。说「特别关注」而不是「白名单」，说「能不能翻到图片」而不是「媒体渲染」。
3. **每题都给默认值**。用户犹豫时直接说「那我按推荐来」，不要停在原地等他纠结。
4. **答不上来不算失败**。有默认值兜底，见每题的分支说明。
5. **七问答完落成一张表**（本篇末尾给模板），后续施工以那张表为准，不靠记忆。

## Q1 · 环境

**话术**

> 先确认下环境：你用的是 Windows 电脑吧？电脑上装了微信桌面版吗？
> 打开微信，点「设置 → 关于微信」，能看到的版本号是多少？

**为什么问**：数据源只有本机微信桌面版，环境不符后面全做不了。

**答案分支**

| 答 | 走向 |
|---|---|
| Windows + 微信 4.x | 继续 |
| 微信 3.x 或更低 | 数据结构不同，本套方法不适用，明说做不到 |
| 手机微信 / macOS | 明说做不到，不要含糊 |
| 不确定版本 | 让他现场打开看，或按文件名判断安装目录版本号 |

## Q2 · 账号

**话术**

> 这台电脑的微信里，你想整理哪个账号的聊天记录？
> 如果电脑上登录过不止一个号，告诉我具体是哪个。

**为什么问**：一台电脑可能登录过多个账号，先定准目标，取错账号后面全部重来。

**两个前置条件（必须讲清楚，否则用户会卡住）**

1. **目标账号须在本机登录过**，并从手机端同步过聊天记录——否则本地根本没有数据文件；
2. **提取密钥时微信必须保持登录运行，且登录的正是目标账号**——密钥只存在于微信进程内存里。
   密钥取回后可缓存复用，此后解密不再需要微信在线。

**怎么帮他找**：让他看微信「设置 → 文件管理」，那里能看到本机登录过的账号目录。

**显示名与 wxid 的对应**：用户报的通常是**显示名**（如「某某老师」），
而数据目录里是 `wxid_` 开头的标识，两者对不上号。
到第 1 步勘察数据目录时要把这层对应核实清楚；**若发现本机登录过多个账号，
必须回来向用户确认是哪一个**，不要自行选择——账号选错，后面全部要推倒重来。

**追问清单**（用户说「不知道有几个号」）

- 让他打开微信设置里的文件管理，看有几个 `wxid_` 开头的目录；
- 或直接问「平时工作用哪个号、生活用哪个号」。

**答不上来的处理**：若他既不记得也不愿查，先按「最近登录的那个」推进，并明确告知取数范围，
后续发现取错可以重来（解密产物可删掉重解）。

## Q3 · 目标

**话术**（**提问时就把三个方向一并给出**，不要先开放再补——普通用户面对开放问题容易卡壳）

> 你想用这些聊天记录解决什么问题？用一句话说就行，不用想太复杂。
> 给你三个方向找找感觉：
> - 随时翻查谁说过什么、把图片视频都调出来看
> - 知道哪个客户多久没回消息、谁该跟进了
> - 从群里统计成交、挖线索
>
> 你说个大概方向就行。

**为什么问**：这一问决定后面全部形态，是七问里最关键的一个。

**答案分支**

| 答 | 路线 | 形态重心 |
|---|---|---|
| 能搜、能翻、能把图片视频调出来看 | A 检索浏览型 | 时间线 + 媒体渲染 + 搜索 |
| 哪个客户多久没回、谁该跟进 | B 联系人管理型 | 档案 + 标签 + 提醒 + 台账 |
| 从群里挖成交、统计线索 | C 内容分析型 | 提取 + 规则解析 + 报表 |

**答不上来的处理**：三个方向已在提问时给出，此处再重复一遍即可。
仍说不出就采用 **SKILL.md 3.1 的默认形态**——按选定范围与布局搭一个简要工作台，之后他自己改。
**不要停在 Q3**。

理由：用户往往在看到自己的数据跑起来之后，才知道真正想要什么。

## Q4 · 会话范围

**话术**

> 第一批先管哪些会话？**我建议先挑 3–5 个最常联系的好友，加 1–2 个最活跃的群**。
> 判断标准很简单：最近一周你主动打开过、或者消息最多的那些。
> 跑通之后随时可以加，不用一次全上。

**为什么问**：不做限制会一次性拉进上千个联系人，首次提取慢、界面也看不清重点。

**答案分支**

| 答 | 处理 |
|---|---|
| 报得出具体名字 | 记进需求档案，作为首批白名单 |
| 「都要」 | 先劝住：起步全量会让首次提取很久，建议先小范围跑通。**用户若坚持，按铁律第 5 条处理**——接受其决定，把风险提示到位，并顺势收紧下一个维度的范围（如时间档） |
| 说不出名字 | 让他打开微信，看最近聊天列表前 5 个 |

**判读标准**：3–5 个好友 + 1–2 个群是推荐区间。多于 10 个会话，提示他首次提取会明显变慢。

## Q5 · 时间范围

**话术**

> 要整理多久的历史？三个档你挑一个：
> **近 3 个月**（推荐，几分钟就能出结果，先看效果）、**近 1 年**（常规回顾够用）、
> **全部历史**（数据最全，但首次提取会很久）。

**为什么问**：历史越长首次提取越慢，先跑小范围能快速验证流程通不通。

**答案分支**

| 答 | 处理 |
|---|---|
| 近 3 个月 | 推荐值，直接用 |
| 近 1 年 | 可以，提示首次时间 |
| 全部历史 | 提醒先小范围跑通流程，再扩到全量 |
| 「越多越好」 | 同上，先小后大 |

## Q6 · 界面风格

**话术**

> 界面上，你有没有想要的样子或者喜欢的风格？
> 说个参照物也行，比如「像某某产品那样」，或者说「简洁一点」。
> 没想法也没关系——**等聊天记录提取出来之后，我按你数据的实际情况推荐一个给你挑**。

**为什么问**：风格是主观偏好，用户自己最清楚；但他通常没有词汇描述。

**答案分支**

| 答 | 处理 |
|---|---|
| 说得出来 | 记进档案，后续读 `05-frontend-layout.md` 落地 |
| 「简洁」这类模糊词 | 追问一次：是要「信息密度高、一屏看很多」还是「留白多、看着轻松」 |
| 两者都要（如「干净轻松，但密度别太低」） | **接受为中间值**，不要逼用户二选一；具体到什么程度，推迟到数据提取完成后按消息量拿捏 |
| 没想法 | **留空**，等数据提取完成后再推荐——那时才知道会话数、消息量、媒体占比 |

**关键**：提问顺序上**不要跳步**。提取之前不要凭空定风格，
没有数据形态支撑的风格选择大概率要推翻。

## Q7 · 功能

**话术**

> 需要给这个工作台搭哪些功能？
> 默认先做三样：**仪表盘看板**（一眼看整体）、**时间线翻记录**（按时间翻聊天）、
> **每日报告**（按天生成摘要）。
> 另外还有几样可以按需加：表格台账、提醒、全文搜索。

**为什么问**：功能决定信息结构，比风格更基础。

**默认三项**（用户不选或说不清时直接采用）

| 功能 | 解决什么 |
|---|---|
| 仪表盘看板 | 打开先看全局，不用一层层点进去 |
| 时间线翻记录 | 按时间顺序浏览某个会话的聊天 |
| 每日报告 | 按天汇总，适合固定节奏使用 |

**可选扩展**：表格台账（导出用）、提醒（该回没回）、搜索（找关键词）。

**注意**：媒体（图片、视频、文件、表情）**默认全部包含，不在这里问**。
用户想砍掉媒体时才需要处理，见 `03-media-layer.md`。

## 需求档案模板

七问答完，把它落成下面这张表。后续所有施工以这张表为准，不靠记忆、不靠回翻对话。

```markdown
## 需求档案

| 项 | 值 | 备注 |
|---|---|---|
| 环境 | Windows 10/11 + 微信 4.x | |
| 目标账号 | <wxid 或用户描述> | 是否已在本机登录过：是 / 否 |
| 一句话目标 | | 路线：A 检索 / B 管理 / C 分析 / 默认形态 |
| 首批会话 | | 好友 N 个，群 N 个 |
| 时间范围 | | |
| 界面风格 | | 留空 = 提取后由 AI 推荐 |
| 功能 | | 默认三项 + 扩展项 |
| 媒体 | 全部包含（默认） | |
```

填完先给用户复述一遍，确认无误再动手。

## 反面清单：无法施工的答案怎么追问

| 用户说 | 问题 | 追问成 |
|---|---|---|
| 「我想要个好看的界面」 | 好看无法施工 | 「信息是希望一屏尽量多，还是留白多一些？」 |
| 「做得智能一点」 | 智能不可测 | 「你希望它自动做什么？比如自动分类、自动提醒？」 |
| 「跟微信一样就行」 | 微信是通用形态，未必适配你的目标 | 「微信用来聊天，你这个是用来看和找，重点会不同。你最常用的是哪一块？」 |
| 「先随便做做」 | 没有验收标准 | 「那先按默认做：三项功能、全部媒体、近 3 个月。跑通了你再提改哪儿。」 |
| 「我也不确定要什么」 | 正常，不必追问 | 直接走默认形态，见 SKILL.md 3.1 |
