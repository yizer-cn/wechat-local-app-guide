# 09 · 参考实现规格（可直接作为提示词）

> **怎么用**：把本篇整段发给 AI，作为「界面与行为」的任务书；技术实现（取密钥、解密、
> 媒体还原）按 `02` / `03` / `08` 三篇执行。三者合起来才是完整任务。
>
> 本篇**只描述页面结构、数据口径与交互规则**，不含任何真实会话名、人名、消息内容或统计值。
> 文中 `<…>` 都是占位符，由执行者用本机实际数据填充。
>
> **形态定位**：单机、只读、离线。数据不出这台电脑；界面只连 `127.0.0.1`。

---

## 0. 交付目标

一套跑在浏览器里的本地工作台，从本机微信库读取数据，提供五个板块：

| 板块 | 一句话作用 |
|---|---|
| 看板 | 打开先看全局：总量、日历、风险、今日待办 |
| 群聊 | 列出群会话，按最近活跃排序，可搜索 |
| 好友 | 列出单聊会话，剔除系统号，可搜索 |
| 日报 | 指定一天的关注对象摘要，可导出 md / pdf |
| 会话档案 | 单个会话的参与者、逐日消息、类型构成 |

**必须满足的三条硬约束**

1. 全程只读微信目录；所有产物写在自己的工作目录。
2. 拿不到的数据就标「未缓存 / 未解析」，**不允许编造、不允许按顺序猜配对**。
3. 任何统计都能追溯到具体消息（点击条目能跳到对应会话）。

## 1. 技术底座（不在本篇展开）

| 层 | 要求 | 依据 |
|---|---|---|
| 取密钥 / 解密 / 消息提取 | 见分册，不允许自行发明 | `02` |
| 媒体还原（图片 / wxgf / 卡片缩略图 / 视频 / 文件） | 见分册 | `03` |
| 环境探测与必经步骤 | 见分册 | `08` |

产出一个**业务库**（SQLite 或等价物），界面只读它，不直接读微信库。
业务库至少含三张表：`conversations`、`messages`、以及可选的 `todos / plans / risk_state` 状态文件。

### 1.1 数据契约（界面依赖的字段）

`conversations`：`id`、`name`、`is_group`、`category`(group/direct/service/system)、
`msg_count`、`first_ts`、`last_ts`、`starred`(0/1)、`unread`。

`messages`：`id`、`conv_id`、`ts`、`day`（本地时区日期串）、`sender`、`is_self`(0/1)、
`kind`（text/sticker/app/image/video/voice/file/location/call/card/system/other）、
`text`、`media`（相对路径，可空）、`media_kind`、`extra`（JSON：格式化后的附加信息）。

**kind 的判定规则**：优先按 `local_type` 映射；`type=49` 再按 `<type>` 细分
（链接卡片 / 文件 / 视频号 / 位置 / 名片）；文件消息只有在**真的定位到本地文件**时才标 `file`，
否则仍算 `app` 并标记未缓存——否则「文件」这一类数量会虚高。

## 2. 全局框架

```
┌──────────────────────────────────────────────────────────┐
│ 品牌名                        版本 <时间戳> · 刷新页面 · 同步新消息 │ 56px
├────────────┬─────────────────────────────────────────────┤
│ 侧栏导航    │ 主内容区                                      │
│ 看板        │                                             │
│ 群聊  <n>   │                                             │
│ 好友  <n>   │                                             │
│ 日报        │                                             │
│ 会话档案    │                                             │
└────────────┴─────────────────────────────────────────────┘
```

**尺寸与配色（照抄即可）**

| 项 | 值 |
|---|---|
| 页面底色 | `#ededed` |
| 侧栏底色 / 悬停 / 选中 | `#f7f7f7` / `#efefef` / `#dedede` |
| 卡片 | `#ffffff`，圆角 8px，`0 1px 2px rgba(0,0,0,.04)` |
| 主文字 / 次要文字 | `#191919` / `#8c8c8c` |
| 强调色（微信绿） | `#07c160` |
| 自己气泡 / 链接蓝 / 未读红 | `#95ec69` / `#576b95` / `#fa5151` |
| 侧栏宽度 | 收起 **184px**；展开群聊/好友时 **334px**，过渡 160ms |
| 顶栏高度 | 56px，sticky |
| 正文字号 / 行高 | 14px / 1.6；次要信息 11–12.5px |

**侧栏行为**

- 默认收起，只显示五个导航项。
- 点「群聊」或「好友」才展开会话列表 + 搜索框；点其它板块收起。
- 搜索框占位符随板块变：`搜索群聊` / `搜索好友`；只过滤当前板块。
- 会话行显示：名称、最后消息时间、未读数（红底徽标，>99 显示 `99+`）、该会话消息总数。
- 排序：**先按最后消息时间倒序**（与微信一致），不要把消息总量当排序键。
- 有「重点关注」标记的会话置顶，单独分组标题 `重点关注`，名称前加绿色 ★。

## 3. 板块规格

### 3.1 看板

自上而下四块，**不要塞其它内容**：

**① 六个 KPI**（等宽自适应网格）：消息总数 / 会话数 / 重点关注数 / 发言人数 / 本人发言（附占比）/ 覆盖天数。

**② 日历（左）+ 风险提示（右）**，两列；窄屏（<1100px）堆叠。

日历：

- 周一为每周首列；每格显示日期数字 + 当日消息数；底部热度条按当日消息量分四档。
- 有重点关注对象消息的日期，左下角一个**绿点**；已写安排的日期，右下角一个**橙点**。
- 可翻月；点任意一天 = **在该页下方编辑那天的安排**（不跳转日报）。
- 日历下方是安排编辑区：显示所选日期 + 多行文本框 + 「保存」；`Ctrl/Cmd+Enter` 也可保存；
  保存成功后提示「已保存 <时间>」。

风险提示（三项，各自带判定口径与计数徽标）：

| 分组 | 口径 |
|---|---|
| @我未回复 | 关注群里 **@ 我**，且此后我在该群没有发言 |
| @所有人未回应 | 关注群里 **@所有人**，且此后我在该群没有发言 |
| 关注好友超 24 小时未回 | 该好友最后一条消息来自对方，且距今 > 24 小时 |

每条右侧三枚胶囊按钮：**已完成 / 忽略 / 待办**。

- `已完成`、`忽略` → 该条**永久**从风险列表消失；记录进入「已处理」，保留 **7 天**后删除。
- `待办` → 该条**留在列表**并加标记，同时往当日待办追加一条（按文本去重）。
- 已处理区默认收起，标题形如 `已处理 <n> 条 · 保留 7 天 ▾`；展开后逐条可「撤销」。
- 超过 7 天的记录不再显示，另起一行说明 `另有 <n> 条超过 7 天，已归档不再显示`。
- **撤销入口必须存在**——删除类操作都要能回退。

**③ 今日待办**

- 当天没有待办时，按风险项自动生成建议（@我 / @所有人 / 好友未回各一条），并注明「已按风险生成，可删改」。
- 每条：勾选框 + 可编辑文本 + 删除按钮；底部一行「输入框 + 添加」。
- 编辑、勾选、删除、新增都即时写入本地文件，刷新不丢。

### 3.2 会话（时间线）

- 顶部固定：会话名、`<类型> · 共 <n> 条 · 最近 <时间>`、右侧会话内搜索框。
- 消息区独立滚动，**打开即定位到最新一条**（不是最旧）。
- 顶部「加载更早的消息」按页向上加载；加载后**视口不跳动**（记录插入前后的高度差并补偿）。
- 消息形态：

| 项 | 规则 |
|---|---|
| 布局 | 头像 36px 圆角 4px，取名字首字；自己的消息靠右、浅绿气泡，对方靠左、白气泡 |
| 气泡 | 圆角 6px，最大宽度 `min(660px, 74%)`；带指向头像的小三角 |
| 群聊显示发送人 | 是；单聊不显示（与微信一致） |
| 日分隔 | 居中胶囊，显示 `YYYY-MM-DD` |
| 系统消息 | 居中灰底胶囊，**不能出现原始 XML** |
| 图片 / 视频 | **不套气泡框**，圆角直接贴底 |
| 引用 | 气泡内先给灰色引用块，被引用的是媒体时摘要成 `[图片]` / `[卡片] 标题` |

- 媒体渲染：
  - 图片：缩略图内联，点击进入灯箱。
  - 灯箱：全屏深色遮罩，`←/→` 或滚轮翻页，显示 `当前/总数`，`Esc` 或点击关闭；
    滚轮加 220ms 节流，避免一次滑动跳好几张。**未缓存/解码失败的图不进入列表**（自然跳过）。
  - 视频：`<video controls preload="none">`；文件：可下载链接。
  - 未缓存的媒体一律显示明确占位文案（例如「图片未缓存 · 微信只为点开过的图建本地副本」），
    不要显示破图图标。
- 会话内搜索：回车触发，命中高亮，显示命中总数，提供「返回会话」。

### 3.3 日报

- 顶部：`重点关注日报 · <日期>` + 当日关注对象消息总数 + `导出 Markdown` / `导出 PDF`。
- 日期切换用横向日期胶囊；当前日期高亮。
- 主体**两列**：`群聊` | `好友`，各列按会话分块：
  - 块头：会话名 + `n 条 · 我 n 条`（群聊再加 `n 人参与`）。
  - 关键词行：从当日文本抽 2-gram 高频词，**排除占位词**（引用/图片/表情/卡片/文件…）。
  - 群聊额外显示 `@我 n 条`。
  - 要点列表：按「长度 / 问句 / 任务词 / 文件 / 链接」打分取原文，每条带时间与发送人。
  - 单聊额外显示「最后一条：时间 谁：内容」。
  - 当日无互动的好友集中列在末尾一行，不要每个都占一个块。
- 导出：Markdown 直接下载；PDF 用本机 Chrome 无头打印（A4，16mm 边距），
  找不到浏览器时返回明确错误并提示改用 Markdown。

### 3.4 会话档案

- 未选会话时提示「先在左侧选择群聊或好友」。
- 内容：KPI（消息数 / 参与者 / 我发言 / 跨度）、参与者排行（**显示总数，不只显示前 N 条**）、
  逐日消息柱、类型构成（中文标签，不显示 `text` / `app` 这类原始键名）。

### 3.5 不展示的会话

`category` 里还有 `service`（公众号 / 企业微信）与 `system`（微信团队、文件传输助手等）。
参考版**不在侧栏展示这两类**，也不把它们计入「群聊 / 好友」的计数。

如果用户要求展示，单独做一个折叠分组，标题如「服务与系统通知」，默认收起；
**绝不要把系统号混进「好友」列表**——那会让「好友未回」这类风险判定产生假阳性。

## 4. 刷新与版本

| 按钮 | 行为 |
|---|---|
| **刷新页面** | 只重新加载界面，不读微信数据。带 `?_r=<时间戳>` 绕过缓存 |
| **同步新消息** | 重新解密 + 重建业务库 + 刷新界面；按钮文字变「同步中…」，完成后自动重载 |

- 服务端对所有响应下发 `Cache-Control: no-store`（媒体文件除外，可长缓存）。
- 页面显示 `版本 <前端文件修改时间>`；服务端在返回 HTML 时注入该时间戳。
- 页面重新获得焦点时比对服务端版本，不一致则按钮变橙色「有新版本」。
- **图片密钥不可用时**：版本标签变红加粗、末尾加「！」，`title` 给出修复指引，
  光标变 `help`。密钥恢复后回到正常灰色。

## 5. 数据口径与质检

| 口径 | 要求 |
|---|---|
| 条数一致 | 源库各会话消息数之和 = 业务库条数，**逐会话零差异** |
| 空字段 | 正文为空、发送人为空的条数必须为 0 |
| 发送人 | 用库内映射表；取不到标「未知成员」，**不要编号占位** |
| 本人识别 | 用本人 sid，不要用「无前缀」推断 |
| 未解析 | `other` 类占比要报出来，并列出类型码 |
| 媒体覆盖率 | 分别统计「已定位 / 未缓存」，如实展示，不做美化 |

交付前跑一遍质检并在界面某处可查（例如看板脚注或关于卡片）。

## 6. 验收清单

- [ ] 五个板块都能打开，无空白页、无控制台报错
- [ ] 群聊 / 好友列表按最近活跃排序，搜索只作用于当前板块
- [ ] 打开会话停在最新一条；上翻加载后视口不跳
- [ ] 图片内联显示，灯箱可键盘/滚轮翻页，未缓存图自动跳过
- [ ] 系统消息、引用消息无原始 XML
- [ ] 风险三项计数与口径一致；三个按钮各自生效；已处理可收起可撤销
- [ ] 日历可写安排，重开仍在；橙点可见
- [ ] 待办可增删改勾，刷新不丢
- [ ] 日报两列齐全，关键词无占位词，导出 md 与 pdf 均可用
- [ ] 刷新按钮与同步按钮行为不同，且都生效
- [ ] 版本号可见；密钥缺失时标签变红加感叹号
- [ ] 逐会话条数与源库零差异

## 7. 禁止事项

1. **不要编造**任何消息、发送人、统计值；缺就写「未缓存 / 未解析」。
2. **不要按顺序或时间近似来配媒体**——配对错误比缺失更难发现。
3. **不要跨会话推断身份**（例如凭同音、同行业猜某人是谁）。
4. **不要上传**任何数据；不要引入需要联网的字体、脚本、CDN。
5. **不要修改**微信目录下任何文件，包括把解密产物写回原目录。
6. **不要为了好看牺牲可核对性**：数字必须能追溯到消息。
